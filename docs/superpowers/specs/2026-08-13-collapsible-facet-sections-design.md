# Сворачиваемые секции фильтров (коллекции / модели / фоны)

Дата: 2026-08-13.

## Проблема

Секции «Коллекции», «Модели» и «Фоны» в форме инструмента — всегда раскрытые
карточки с прокруткой (`facet-section`, `max-height` + `overflow: auto`). Три
раскрытых блока занимают почти весь экран, хотя по запросу владельца из трёх
актуальна лишь часть: модели имеют смысл только при выбранной одной коллекции,
фоны — только при выбранной хотя бы одной модели.

## Цель

Превратить секции в компактные сворачиваемые панели («окошки») с автооткрытием
по правилам выбора и возможностью сворачивания тапом. Поиск остаётся внутри
каждой раскрытой панели (уже есть во всех трёх).

## Требования

1. **Сворачиваемость.** У каждой секции — шапка с заголовком, счётчиком
   выбранного и чевроком. Тело скрыто/показано анимацией техникой
   `grid-template-rows: 0fr → 1fr` (как у тостов).
2. **Автооткрытие:**
   - Коллекции — всегда раскрыты, ручного сворачивания нет.
   - Модели — раскрыты тогда и только тогда, когда выбрана ровно одна коллекция
     (0 или >1 коллекции → схлопнуты, в шапке подсказка «выбери одну коллекцию»).
   - Фоны — раскрыты, когда выбрана хотя бы одна модель (иначе схлопнуты,
     подсказка «выбери модель»).
3. **Ручной тап.** Когда секция валидна, тап по шапке сворачивает/разворачивает её
   и запоминается до следующей смены выбора. Когда секция невалидна — тап не
   работает, состояние принудительно закрыто.
4. **Автоматика при смене выбора.** Смена коллекции сбрасывает ручные
   переключатели «Модели» и «Фоны»; смена модели сбрасывает переключатель «Фоны».
   После сброса секции снова подчиняются правилам автооткрытия.
5. **Счётчики в шапке:** коллекции — число выбранных или «все» (при
   `collection_all`); модели/фоны — число выбранных; при невалидном состоянии —
   текст-подсказка вместо счётчика.

## Изменения

Только фронтенд: `webapp/js/app.js` и `webapp/css/tokens.css`.

### `webapp/js/app.js`

- `state.overlay.sectionOpen: Record<string, boolean>` — ручные тапы. Инициализируется
  пустым в `openTool()`.
- `toolFacetSection()` переписывается на панели: для каждой секции вычисляется
  `available` (коллекции — всегда; модели — `collectionCount === 1`; фоны —
  `collectionCount === 1 && modelCount > 0`), затем `open` =
  `available && (sectionOpen[key] ?? true)`.
- Невалидная секция рендерит закрытую шапку без кнопки-тапа и с подсказкой.
- Клик `data-action="toggle-section"` / `data-section="model"|"backdrop"`:
  если секция валидна — инвертирует `sectionOpen[key]` и рендерит.
- Тап чипов коллекции и модели (в `click` обработчике, ветка `chip`) и действие
  `select-all` сбрасывают нужные ключи в `sectionOpen` перед рендером.

### `webapp/css/tokens.css`

- Новые классы: `.facet-panel`, `.facet-panel__head` (кнопка/шапка), `.facet-panel__title`,
  `.facet-panel__meta`, `.facet-panel__chev` (поворот при открытии),
  `.facet-panel__body` (коллапсируемый контейнер `grid-template-rows`).
- Старые `.facet-section--locked` и хинты в теле заменяются на подсказки в шапке.

## Что не меняется

- Бэкенд, API, данные, фильтры — без изменений.
- Логика доступности секций (`modelsOpen` / `backdropsOpen`) уже совпадает с
  правилами из требований; меняется только представление (коллапс вместо
  «заблокированной» карточки).

## Проверка

- Мануальная: формы tracker, automessage (много-выбор) и sniping, ordering
  (одиночный выбор) — автораскрытие при выборе коллекции/модели, схлопывание при
  0 или >1 коллекциях и при 0 моделях, ручной тап по валидным секциям.
- Возврат при `prefers-reduced-motion`.
