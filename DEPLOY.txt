==============================================================
 CIABATTA TOOLS - ГАЙД ПО ДЕПЛОЮ
 (ботхост / VPS / Docker)
==============================================================

Проект - Telegram-бот с мини-приложением и тремя инструментами
для работы с NFT-подарками. Бот и мини-app работают в ОДНОМ
контейнере на ОДНОМ порту: именно так устроены ботхосты.

За покупкой доступа - @awhoreable


--------------------------------------------------------------
0. ЧТО ПОДГОТОВИТЬ ЗАРАНЕЕ
--------------------------------------------------------------

1) ТОКЕН БОТА
   @BotFather -> /newbot -> запиши токен.

2) API_ID И API_HASH
   https://my.telegram.org/auth -> API development tools ->
   создай приложение (название любое, платформа Android).

   ВАЖНО: это НЕ то же самое, что токен бота. Подарки читаются
   от имени пользователя (MTProto), боту такое недоступно.
   Нужны обе вещи одновременно.

3) КЛЮЧ ШИФРОВАНИЯ
   Сессии Telegram и API-ключи хранятся в базе зашифрованными.
   Сгенерируй 64 hex-символа:

       python3 -c "import secrets; print(secrets.token_hex(32))"

   ЕСЛИ ПОТЕРЯТЬ ЭТОТ КЛЮЧ - все сессии станут нечитаемыми, и
   всем придётся логиниться заново. Сохрани его отдельно.

4) ДОМЕН С HTTPS
   Мини-app работает ТОЛЬКО по https - это требование Telegram,
   не наше. Варианты:
     - свой домен + reverse-proxy (nginx/caddy) на порт 8080;
     - быстро и бесплатно: cloudflared tunnel.

5) КНОПКА МИНИ-APP
   @BotFather -> /mybots -> твой бот -> Bot Settings ->
   Menu Button -> укажи тот же URL, что в PUBLIC_URL.


--------------------------------------------------------------
1. ПЕРЕМЕННЫЕ ОКРУЖЕНИЯ
--------------------------------------------------------------

ОБЯЗАТЕЛЬНЫЕ (без них бот не стартует и скажет, чего не хватает):

  BOT_TOKEN=123456:AA...             от @BotFather
  TG_API_ID=12345678                 с my.telegram.org
  TG_API_HASH=abc123...              с my.telegram.org
  CIABATTA_SECRET_KEY=<64 hex>       ключ шифрования из п.3
  PUBLIC_URL=https://твой-домен      https, без слэша на конце

ВАЖНЫЕ:

  OWNER_TG_ID=123456789              твой Telegram ID, открывает
                                     команду /keys.
                                     Узнать ID: @userinfobot
  DRY_RUN=true                       РЕЖИМ СИМУЛЯЦИИ.
                                     true = ничего не покупается.
                                     Оставь true до первой проверки.
  SUPPORT_CONTACT=@awhoreable        куда писать за доступом

НЕОБЯЗАТЕЛЬНЫЕ:

  DATABASE_URL=                      по умолчанию SQLite в /app/data.
                                     Для Postgres:
                                     postgresql+asyncpg://user:pass@host/db
  PORT=8080                          ботхост обычно задаёт сам
  MAX_SPEND_PER_BUY_TON=5            лимит на одну покупку
  MAX_SPEND_PER_DAY_TON=50           лимит в сутки
  MRKT_TOKEN=                        токен MRKT вручную; обычно не нужен,
                                     берётся через твою сессию

Ключ Gift Satellite в переменные НЕ пишется - он вводится
сообщением в боте командой /gskey и хранится зашифрованным.


--------------------------------------------------------------
2. ДЕПЛОЙ НА БОТХОСТ (bothost.ru и аналоги)
--------------------------------------------------------------

1) Запушь репозиторий:

       git remote add origin https://github.com/pexepo/ciabattatools.git
       git push -u origin main

2) В панели хоста выбери "Deploy from Dockerfile"
   (или "Docker deploy" - название зависит от панели).

3) Добавь переменные окружения из раздела 1.

4) ОБЯЗАТЕЛЬНО включи постоянное хранилище (persistent volume /
   постоянный диск) и примонтируй его в:

       /app/data

   Без этого при каждом рестарте пропадут сессии и база - все
   пользователи разлогинятся. Это самая частая ошибка первого
   деплоя.

5) Порт: 8080 (или тот, что хост подставляет в PORT).

6) Проверка, что поднялось:
     - открой https://твой-домен/healthz
       должно вернуться: {"ok":true,"dry_run":true}
     - напиши боту /start - он должен ответить.


--------------------------------------------------------------
3. ДЕПЛОЙ НА VPS
--------------------------------------------------------------

       git clone https://github.com/pexepo/ciabattatools.git
       cd ciabattatools
       cp .env.example .env
       nano .env                      # заполни переменные
       docker compose up -d --build

Логи:      docker compose logs -f
Рестарт:   docker compose restart
Стоп:      docker compose down

HTTPS через caddy (Caddyfile):

       твой-домен.ru {
           reverse_proxy localhost:8080
       }

Быстрый вариант без домена:

       cloudflared tunnel --url http://localhost:8080

Он выдаст адрес вида https://xxx.trycloudflare.com - его и
укажи в PUBLIC_URL и в кнопке мини-app у @BotFather.
Учти: бесплатный адрес меняется при каждом перезапуске
туннеля, для постоянной работы нужен свой домен.


--------------------------------------------------------------
4. ЛОКАЛЬНЫЙ ЗАПУСК
--------------------------------------------------------------

       python3 -m venv .venv
       .venv/bin/pip install -r requirements.txt
       cp .env.example .env           # заполни
       .venv/bin/python -m src.bot.main                        # бот
       .venv/bin/python -m uvicorn src.api.app:app --port 8080 # API

Тесты:

       .venv/bin/python -m pytest tests/ -q


--------------------------------------------------------------
5. ПЕРВЫЙ ЗАПУСК: ПОРЯДОК ДЕЙСТВИЙ
--------------------------------------------------------------

1) /start в боте.

2) Бот попросит ключ доступа. Твой ключ - PEXEPO
   (регистр не важен, можно писать pexepo).
   Всего в системе 100 ключей плюс твой.

   ОТКУДА БЕРУТСЯ 100 КЛЮЧЕЙ. Они выводятся из
   CIABATTA_SECRET_KEY - один и тот же секрет всегда даёт
   один и тот же набор. Поэтому:

     - рестарт не создаёт новые ключи;
     - если база потерялась, ключи восстановятся сами;
     - НО при смене CIABATTA_SECRET_KEY набор станет другим,
       и все проданные ключи перестанут работать.

   Отсюда правило: секрет задаётся один раз и не меняется.
   Храни его копию отдельно от сервера.

   Посмотреть свои 100 ключей (чтобы выдавать покупателям):

       .venv/bin/python -c "import sys;sys.path.insert(0,'.');\
       from src.core import licenses,config;\
       print('\n'.join(licenses.derive_keys(config.SECRET_KEY)))"

   Список не публикуй и не храни в репозитории: это
   предъявительские ключи, кто знает - тот и пользуется.

3) Команда /keys покажет, сколько ключей активировано.
   Работает только для OWNER_TG_ID.

4) Нажми "Подключить аккаунт" и пройди вход:
   телефон -> код -> пароль 2FA, если он стоит.

   Все три сообщения бот удаляет из чата сразу после обработки
   и не пишет в логи.

5) После входа появится кнопка "Открыть Ciabatta Tools".

6) DRY_RUN. Пока включён - реальных покупок нет, это безопасный
   режим для проверки. Выключается в приложении:
   Профиль -> Режим симуляции -> Боевой режим.
   Приложение попросит подтверждение - это осознанно.


--------------------------------------------------------------
6. ЕСЛИ ЧТО-ТО НЕ РАБОТАЕТ
--------------------------------------------------------------

БОТ НЕ ОТВЕЧАЕТ НА /start
  Смотри логи. При нехватке переменных бот пишет прямо, каких
  именно, и завершается - это не молчаливая ошибка.

В ЛОГАХ "unable to open database file" И "bot exited"
  Том /app/data примонтирован, но не записывается процессом
  контейнера (обычно - том принадлежит root, а процессам нужен
  пользователь ciabatta). Начиная с этого коммита entrypoint сам
  чинит права тома при старте - передеплой репозиторий. Если
  ошибка осталась - том смонтирован read-only: в панели хоста
  проверь, что постоянное хранилище в /app/data доступно на
  запись.

КНОПКА МИНИ-APP НЕ ПОЯВЛЯЕТСЯ
  PUBLIC_URL не начинается с https:// - Telegram отклоняет такие
  кнопки. Бот в этом случае пишет об этом сообщением.

ПРИЛОЖЕНИЕ ПИШЕТ "Открой приложение через бота"
  Это 401: Telegram не подтвердил подпись. Так и должно быть,
  если открыть адрес в обычном браузере - мини-app работает
  только изнутри Telegram.

ПРИЛОЖЕНИЕ ПИШЕТ "Telegram-аккаунт не подключён"
  Сессии нет или она отозвана. Открой бота, нажми "Подключить
  аккаунт". Telegram мог отозвать сессию сам - например, при
  смене пароля.

ПОСЛЕ РЕСТАРТА ВСЕ РАЗЛОГИНИЛИСЬ
  Не примонтирован том в /app/data. См. раздел 2, пункт 4.

НЕ РАСШИФРОВЫВАЮТСЯ СЕССИИ ИЛИ КЛЮЧИ
  Изменился CIABATTA_SECRET_KEY. Старые данные восстановить
  нельзя - нужно залогиниться заново и заново ввести /gskey.

КАТАЛОГ ПУСТОЙ ИЛИ ОШИБКА MRKT
  У MRKT нет публичного API, интеграция идёт через приватные
  эндпоинты мини-аппа, и они могут меняться без предупреждения.
  Что искать в логах: 401 - токен просрочен, перелогинься;
  429 - слишком часто, клиент сам подождёт и повторит.


--------------------------------------------------------------
7. ЧТО ВАЖНО ЗНАТЬ
--------------------------------------------------------------

ПРО ГАЗ. Комиссия MRKT около 2%, но газ TON - примерно 0.1 TON
на покупку и столько же на продажу. На подарках за 2-5 TON газ
выходит дороже комиссии и съедает прибыль. Учитывай это при
выставлении цен: "без комиссий" не значит "бесплатно".

ПРО АВТОМАТИЗАЦИЮ. Автоматическая торговля может нарушать
правила маркета. Риск блокировки аккаунта лежит на владельце.
Лимиты трат (MAX_SPEND_*) и DRY_RUN существуют именно поэтому.

ПРО ВТОРОЙ АККАУНТ. Для авто-сообщений лучше подключить
отдельный аккаунт: рассылка незнакомым людям - основная причина
ограничений в Telegram, и терять на этом основной аккаунт с
подарками не стоит.

ПРО ОРДЕРА. У MRKT нет открытого стакана заявок, поэтому
показывается только самый высокий ордер - его достаточно, чтобы
перебить. Придумывать остальные цифры было бы неправильно.
